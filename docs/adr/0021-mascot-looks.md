# ADR-0021：角色外觀（配色與特效）

- 狀態：**已採用**（2026-10-29）
- 日期：2026-10-29
- 相關：[ADR-0010](0010-mac-animation-principles.md)（動畫原則；本 ADR 第 4 節是它的例外）、[ADR-0016](0016-mascot-character.md)（角色、重畫頻率、動畫程度）、[ADR-0008](0008-mac-panel-layout.md)（選單列圖示）
- 來源：配色挑選頁（網址與定案記在工作資料夾的 `design/mascot/PALETTE-PICKS.md`，不在 repo）。色值與畫法以頁面的 `PAL` 陣列與 `body`、`fxGrid`、`fxWire`、`fxNeon` 函式為準

## 背景

角色的顏色一直跟著服務：Claude 珊瑚、Codex 青瓷（MASCOT-SPEC 第 2 節）。使用者在挑選頁從 40 多個配色裡定案了 12 個，另外保留預設的服務色：

- 單色或漸層：D3 珍珠白、T5 深空、C1 草莓牛奶、C3 棉花糖、C4 蜜桃、M1 石墨、M2 霧灰；
- 特效：X9 LED 點陣、X10 8-bit 像素、X8 霓虹線條、X4 線框球、X3 ASCII 白。

使用者要求：

- 收合時的迷你角色也看得到特效；
- 特效會動，收合時在 AI 工作中動（動畫本身代表「在跑」）；
- （2026-10-29 追加，「收合時的動態」）收合時**所有外觀**在 AI 工作中都會動：一般配色是簡化的敲鍵盤；
- 睡著時收合也有慢慢的呼吸加一個飄起的小 z。

這和 ADR-0010「收起來就不動」不同，要寫清楚例外與代價。

## 決定

### 1. 資料：`shared/mascot-looks.json`

清單、分組、顏色放在共用資料夾，Mac 以資源檔打包，Windows 之後畫角色時讀同一份。

- 每個外觀有：代號、名稱、分組、`style`、顏色。顏色是「#RRGGBB」。
- `style` 決定用哪些顏色：
  - `solid`：三階 `light`／`mid`／`shade`，畫法同服務色；
  - `linear`：`stops` 依 `angle` 畫直線漸層，再疊上球面的高光與陰影；
  - `led`、`pixel`、`neon`、`wire`、`ascii`：特效，`color` 是主色。
- `glow` 是光暈色；霓虹另有 `glow_scale` 1.4。
- `eye` 是眼睛的顏色，沒寫時是深色。
- `blush` 表示有腮紅。

預設「跟著服務」不在清單裡：設定存 `nil`，畫服務色，和現在一樣。

- 設定存代號（`notch.look`）。
- 清單之後拿掉某個代號時，存著的代號找不到，就退回跟著服務，不會壞掉。
- 讀不到這份檔案時，設定頁不顯示「角色外觀」，只有服務色。

UsageKit 的 `MascotLook` 解析並檢查：

- 代號不重複；
- 分組存在；
- 每種 `style` 需要的顏色都有。

測試讀 repo 裡的這份，確認清單就是使用者定案的 12 個，以及深色身體與可愛風的設定。

### 2. 畫法

Mac 的 `MascotLookRenderer` 用 CoreGraphics 畫身體。瀏海的 Canvas（`withCGContext`）、設定頁預覽、選單列圖示共用同一份。數值照挑選頁。

| 外觀 | 畫法 |
|---|---|
| 單色（D3、C1、C4、M1、M2） | 同服務色的三階球面漸層，只換顏色 |
| 漸層（T5、C3） | 直線漸層，加左上高光（白 55%→0）與右下陰影（黑 0→40%） |
| X9 LED 點陣 | 格子取樣球面亮度：亮的點混主色，暗的點是 7% 白的熄燈；一道往下掃的光 |
| X10 8-bit 像素 | 格子取樣亮度分三階（主色混白 60%／主色／混黑 50%） |
| X8 霓虹線條 | 深色球加發光外框，外框呼吸（亮度 75%～100%） |
| X4 線框球 | 深色半透明球加經線（會轉，看滑鼠時跟著轉向）與緯線 |
| X3 ASCII 白 | 依亮度選字元 `.:-=+*#%@`，偶爾跳一格 |

- **格子特效的亮度**：挑選頁是把球畫在暫存畫布再取樣。這裡直接解兩圓錐形漸層（同一組圓心、半徑與色標），得到每格中心的亮度，不用暫存點陣，每格只算一次方程式。
- **眼睛的格子**：膠囊眼睛落在的格子當成最暗：ASCII 不畫字，LED 是熄燈。
- **迷你角色**（半徑小於 12，收合時約 9）用格子少的畫法：
  - LED 7×7 加暗色眼睛；
  - 像素 9×9；
  - ASCII 只用 `.:+*`，加亮眼；
  - 線框 3 條經線、1 條緯線；
  - 霓虹照常。

  LED、像素只畫落在圓內的格子（迷你時圓的 90%），不會看起來是方形。
- **眼睛**：
  - 深色身體（深空、石墨）用亮色；
  - 可愛風（草莓牛奶、棉花糖、蜜桃）加腮紅（同右鍵「害羞」的腮紅，強度 0.9）；
  - ASCII、線框、霓虹的眼睛發光（陰影半徑 0.15R）；
  - 像素的膠囊眼睛對齊格子、實心；
  - 表情（擔心的小圓點、×、閉眼、開心、眉毛）照原本的畫法，只換成外觀的眼睛顏色。LED、像素沒有膠囊眼時，另外畫在格子上面；LED 的表情用暗琥珀（混主色 35%），落在格子之間的黑縫也看得到。
- **手**：
  - 線框、霓虹是發光的圓圈；
  - 漸層照身體；
  - 其他特效用主色的三階。
- **過場**：從白色變成服務色的那一段（ADR-0016 的 `tint`）對外觀也適用：
  - 單色從白色漸變；
  - 其他外觀先畫白色的球，外觀的身體以 `tint` 的不透明度疊上去；
  - 眼睛顏色從深色跟著漸變。

### 3. 設定頁

「瀏海面板」的「角色」下面加「角色外觀」：

- 「跟著服務」加 12 個外觀，排成一片，順序照分組：基本、科技、可愛、極簡、特效；
- 每格是用實際角色畫的靜態預覽，左邊展開時的大小（半徑 16）、右下收合時的迷你角色（半徑 9）；
- 分組名稱與說明放在滑鼠提示與 VoiceOver（例如「特效：線框球，經緯線組成的球，會慢慢轉」），不另外佔行；
- 選中的外框是強調色，VoiceOver 讀「已選取」；
- 預覽靜態、設定頁開著不重畫。

### 4. 什麼時候動（ADR-0010 的例外）

| 狀態 | 畫面 | 怎麼重畫 |
|---|---|---|
| 展開 | 特效動 | 原本就在重畫時（眨眼、看滑鼠、工作、睡覺，ADR-0016 第 7 節）跟著那個頻率動；原本會完全停住時改成每秒 12 次，只重畫角色那一小塊 |
| 收合、AI 工作中 | 會動的特效照特效動；其他外觀（服務色、單色、漸層、像素）簡化的敲鍵盤：小手上下、身體輕晃，不畫鍵盤 | Core Animation 循環播放預先畫好的一輪（每秒 12 格） |
| 收合、睡著 | 慢慢的呼吸（約 4.4 秒一次）加一個往右上飄的小 z；特效停在那一格 | 同上，每秒 4 格 |
| 收合、閒置、需要你 | 靜態的一格 | 不重畫（同現在） |
| 收合時看滑鼠轉頭 | 照原本（ADR-0016） | 視線轉完再回到上面那一列 |
| 動畫「簡單」「關閉」、系統「減少動態效果」 | 靜態的一格（收合時也沒有敲鍵盤、呼吸） | 照原本的規則 |
| 選單列圖示 | 靜態的一格 | 只在內容改變時重畫（ADR-0008） |

- 8-bit 像素沒有隨時間變的部分；收合工作中和一般配色一樣敲鍵盤。
- 「工作中」「睡著」照 ADR-0017 的 AI 狀態（`MascotDirector.mode`）。
- **特效的時鐘**：特效停住時停在最後一格，再動時從那一格接著走，不會跳回第 0 格。收合動畫播完才停。
- **靜態的一格**（動畫簡單、關閉、減少動態效果）：
  - 霓虹是最亮的時候；
  - 線框球的經線停在 0 度，但仍跟著視線轉；
  - LED 沒有掃描光；
  - ASCII 不跳字。

**收合時用 Core Animation 循環播放**

收合時角色的位置、視線、眼睛都停住，只有小範圍在動，所以：

1. 進入「收合工作中」或「收合睡著」時，把一輪畫成圖片，交給 Core Animation 的關鍵影格動畫（`contents`、不連續、無限重複）：
   - 迷你角色周圍 R×7 的範圍，含光暈；
   - 一輪長度取動態本身週期的整數倍，接回開頭看不出斷點：

     | 動態 | 一輪 |
     |---|---|
     | 敲鍵盤 | 2π×310 毫秒（敲 5 下、晃一次） |
     | 呼吸 | 2π×700 毫秒 |
     | 霓虹 | 2π×480 毫秒 |
     | 線框 | 2600π／經線數 |
     | LED | 掃描週期的倍數，約 3 秒 |
     | ASCII | 27 次跳字 |

2. 循環在視窗伺服器裡播，App 自己每一格都不用重畫。
3. 模式、外觀、動畫程度改變或展開時重建或停掉，並釋放圖片。一輪約 18～36 張、每張約 140 px 見方，合計不到 3 MB。

原本用 SwiftUI 每秒更新 12 次（只重畫角色那一小塊、放在獨立的畫面），實測收合工作中仍有約 3% CPU。取樣看到的時間幾乎都在 SwiftUI 的排版與送出，畫角色本身不到一成，所以降頻或簡化畫法都到不了 1%。

**為什麼是例外**：

- ADR-0010 第 1 節要求收起來就停止動畫；
- ADR-0016 第 7 節讓收合的瀏海除了看滑鼠，都不重畫；
- 使用者明確要求收合時，AI 工作中、睡著時都看得到動態。

這樣做的理由：

- 動態本身傳達 AI 的狀態（在跑、在睡），和狀態一致；
- AI 閒置或需要你時，App 照樣完全不重畫；
- 用 Core Animation 播，App 的 CPU 和不動時幾乎一樣（第 7 節）。

**效能門檻**（`scripts/measure-look-perf.sh`）：

- Debug 版，方法同 ADR-0010 第 3 節，每個外觀各跑一次；
- 時間表依序是：收著工作中、收著睡著、收著閒置、展開。

| 項目 | 門檻 |
|---|---|
| 收合、工作中 | CPU ≤ 1% |
| 收合、睡著 | ≤ 0.5% |
| 收合、閒置 | ≤ 0.3% |
| 展開待著 | 只記錄，不設門檻（同 ADR-0016 展開時） |

實測見第 7 節。

### 5. 選單列圖示

選了外觀時，角色樣式的圖示用該外觀的靜態畫面：

- 單色換顏色；
- 其他用同一份畫法（半徑 6.8、靜態）；
- 特效是在黑色瀏海上設計的：選單列先鋪一個深色圓底（灰 6%、不透明度 92%），淺色選單列上才看得到球的輪廓與眼睛。

額度的表情（膠囊、小圓點、×、半閉、閉眼）照 ADR-0008 第 1 節，眼睛換成外觀的顏色。資料過期時仍是灰白（不用外觀），「過期」不能被外觀蓋掉。

### 6. 截圖

- 截圖基準加三張：
  - `notch-looks-expanded`：每個外觀展開，特效畫第 1.5 秒那一格；
  - `notch-looks-collapsed`：每個外觀收合時 AI 工作中、睡著（Core Animation 那一輪的 30% 處）與閒置；
  - `notch-collapsed-motion`：服務色收合時敲鍵盤與睡著呼吸各四格。
- `menubar-icons-*` 加每個外觀的角色圖示（七種額度狀態）。
- 設定頁的截圖包含外觀選單。

### 7. 實測

2026-10-29，Apple M5、macOS 27.0.1，Debug 版，`scripts/measure-look-perf.sh`（報表 `scripts/look-perf-summary.py`）。數字是 `ps` 的 CPU%，每段開始後 5～28 秒的平均，**包含** `UsageStore` 每分鐘的更新（ADR-0010 第 3 節；Codex C-03）。量測時游標固定，真的滑鼠停在瀏海上也不展開。

| 外觀 | 收合、工作中 | 收合、睡著 | 收合、閒置 | 展開待著 |
|---|---|---|---|---|
| 跟著服務（敲鍵盤） | 0.03% | 0.15% | 0.05% | 2.31% |
| X9 LED 點陣 | 0.05% | 0.08% | 0.05% | 6.77% |
| X8 霓虹線條 | 0.06% | 0.06% | 0.02% | 5.98% |
| X4 線框球 | 0.02% | 0.01% | 0.05% | 4.88% |
| X3 ASCII 白 | 0.05% | 0.16% | 0.05% | 5.16% |
| X10 8-bit 像素（敲鍵盤） | 0.06% | 0.00% | 0.05% | 2.05% |
| T5 深空（敲鍵盤） | 0.05% | 0.10% | 0.07% | 2.39% |

- 收合的三項都在門檻內（≤ 1%、≤ 0.5%、≤ 0.3%）。
- 展開待著的特效外觀是 4.9～6.8%，比服務色的 2.3% 高。原因是特效每格要畫格子、字形或發光的線，而展開時 SwiftUI 每秒 30 次重畫整個角色。展開時沒有門檻（同 ADR-0016），記在 BACKLOG，之後可以把展開時的特效也改成 Core Animation。
- 過程：
  - 第一版用 SwiftUI 每秒 12 次，收合工作中 3.1～3.8%；
  - 只重畫小框、放進獨立的畫面後是 2.9～3.0%；
  - 改用 Core Animation 後降到 0.1% 以下。

## 考慮過的做法

- **收合時一律靜態**：最省電，符合 ADR-0010，但使用者明確要收合時看得到特效。
- **收合時一直動**：閒置時也每秒重畫 12 次，違反「收起來不吃 CPU」，不採用。
- **展開時才動、收合靜態，加一個「收合也動」的開關**：多一個設定；使用者的要求是工作中動、閒置停，這本身就是好的預設。不採用；要的話之後再加。
- **格子特效先畫在暫存點陣再取樣（照挑選頁）**：每格要讀像素，而且要另外管理點陣的生命週期。解析計算亮度結果相同（同一組漸層參數），較省。
- **收合時用 SwiftUI 每秒更新 12 次**：先試過只重畫角色那一小塊、再放到獨立的畫面，收合工作中仍約 3%（取樣：時間幾乎都在 SwiftUI 的排版與送出）。改用 Core Animation 循環播放。
- **收合時降到每秒 3 次**：到得了 1%，但敲鍵盤與特效會一格一格跳。Core Animation 的做法維持每秒 12 格、CPU 更低。
- **ASCII 用 SwiftUI `Text` 畫字**：每格排版文字很花 CPU（睡著的 z 就是因此改成線段）。改用 CoreText 的字形外框，每個大小只建一次。
- **外觀資料寫在 Swift 裡**：Windows 之後要畫同樣的角色，放 `shared/` 才不會兩邊各寫一份。

## 後果

- 新增 `shared/mascot-looks.json`、UsageKit `MascotLook`、Mac 的 `MascotLookRenderer`、`MascotLookPicker`。
- `MascotRenderRate` 多一個 `.effect`：只有特效在動（展開時每秒 12 次），或收合時由 Core Animation 播（`MascotEffectLoop`）。
- 收合時 AI 工作中或睡著，迷你角色會動（所有外觀）；App 本身不重畫，由視窗伺服器播放預先畫好的一輪（量測見第 7 節）。
- 進入那個狀態時要畫一輪（18～36 張），之後到狀態改變前不再畫。
- ADR-0010 第 1 節、ADR-0016 第 7 節加註指回本 ADR；MASCOT-SPEC、設計 skill 同步更新。
- 格子特效的眼睛格不跟著 roll（揮手晃動時眼睛不跟頭轉，Fable F-11），記在 BACKLOG。
- Windows 的角色（BACKLOG 第 12 節）之後讀同一份資料。畫法要照本 ADR 第 2 節重寫一份 C#（Direct2D／Win2D），沒有 golden；要比對就用截圖。
