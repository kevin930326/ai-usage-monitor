# ADR-0010：Mac 面板與統計視窗的動畫原則與效能量測

- 狀態：**提議中**
- 日期：2026-10-23
- 相關需求：FR-25（改寫）、NFR-8、NFR-10
- 相關：[ADR-0008](0008-mac-panel-layout.md)（版面）

## 背景

FR-25 原本是「面板加入動態或 3D 視覺效果，只在面板開啟時執行」。設計確定了 17 個具體的動畫（規格第 6 節），需要一致的規則決定：什麼時候可以動、動多久、怎麼確認沒有在背景耗電。選單列 App 是常駐程式，面板大部分時間是關閉的；NFR-8 要求關閉時不佔 CPU／GPU。

## 決定

### 1. 五條規則

1. **只在面板或統計視窗開啟時執行。** 選單列圖示只允許數值改變時 ≤ 0.3 秒的轉場，不得有持續或循環的動畫。面板關閉時所有動畫，以及為面板或動畫而設的計時器（`TimelineView`、`Timer`、`CADisplayLink`）都要停止。唯一的例外是 `UsageStore` 既有的每 60 秒計時器（第 3 節）：它負責選單列圖示的過期與重置判斷，面板關閉時仍保留，但只能更新資料、不得啟動動畫，隱藏的面板因此最多每分鐘重算一次，這部分包含在「關閉後 1 分鐘 ≤ 0.3%」的門檻內。`MenuBarExtra` 的面板關閉時視圖不會釋放（視窗只是被收起），所以面板以視窗的 occlusion 與 key 狀態判斷是否看得見（ADR-0008 第 3 節），看不見時：停止動畫、回到靜止狀態，並把 `Text(date, style: .relative)` 這類系統自動更新的文字換成固定文字——實測它在收起的視窗中仍會定時重算，關閉後 CPU 平均 0.7%，換掉後為 0.1%。統計視窗關閉時釋放。
2. **尊重「減少動態效果」。** `accessibilityReduceMotion` 為真時，所有位移、縮放、旋轉、描繪、光芒、滾動數字一律改為直接顯示最終狀態；只允許 ≤ 0.15 秒的淡入淡出（Apple 的建議做法）。深淺色切換照系統。
3. **一次性、有終點。** 每個動畫都有固定長度：單次 ≤ 1.2 秒（多數 0.2～0.6 秒），重複類（骨架掃光、服務狀態的橘點）最多 3 次、總長 ≤ 4 秒，之後停止。
4. **由資料改變觸發，不輪詢。** 動畫只在面板出現、資料改變（`usage.json` 有新內容）、使用者操作時開始；不為了動畫額外讀檔或查詢資料庫。
5. **以 SwiftUI 內建的動畫為主。** `withAnimation`、`.contentTransition(.numericText())`、`.transition`、`PhaseAnimator`／`KeyframeAnimator`（有固定終點時）；不用 Metal shader 或 SceneKit（FR-25 原本的 3D 效果取消，除非之後另有 ADR）。

### 2. 動畫清單與階段

| 位置 | 動畫 | 長度 | 階段 |
|---|---|---|---|
| 主圓環 | 打開面板時兩個圓環從 0 畫到目前位置；數字滾動；剩 < 20% 時外圈顏色過渡到紅色 | 0.6 秒 | 第一階段 |
| 用量條 | 從左長到目前長度，預期標記稍後淡入；資料更新時只動變化的那一條 | 0.5 秒＋0.2 秒 | 第一階段 |
| 更新按鈕 | 讀取時圖示旋轉一圈；完成後狀態點閃一下 | 0.6 秒 | 第一階段 |
| 額度重置 | 某額度的 `resets_at` 改變或 `isReset` 由假變真時，對應的服務圖示閃一下光芒（只在面板開啟時；關閉期間發生的不補播） | 0.8 秒 | 第一階段 |
| 卡片收合 | 內容向上收起、下方卡片上移；箭頭旋轉 90° | 0.25 秒 | 第一階段 |
| 深淺色切換 | 顏色平滑過渡 | 0.3 秒 | 第一階段 |
| 走勢曲線 | 由左往右描繪，最後的圓點輕彈一下；切換額度時交叉淡入；無紀錄區塊淡入 | 0.6 秒 | 第二階段 |
| 建議接下來用 | 從上方滑入；推薦的服務改變時圖示交叉淡入 | 0.3 秒 | 第二階段 |
| 重置時間軸 | 圓點依序滑到位置；重置時圓點飛向「現在」後消失，同時觸發重置光芒 | 0.5 秒 | 第二階段 |
| 第一次使用 | 骨架畫面一道光由左往右掃過（最多 3 次）；資料出現時交叉淡入 | 1.2 秒 × 3 | 第二階段 |
| 服務切換 | 數字滾動，長條與熱力圖交叉淡入換色 | 0.3 秒 | 第三階段 |
| 統計數字 | numericText 滾動；連續天數創新紀錄時 🔥 跳一下（每個紀錄只跳一次） | 0.4 秒 | 第三階段 |
| Token 長條 | 由下往上依序長出（每根延遲 15ms）；滑鼠移上去放大並顯示數值 | ≤ 0.9 秒 | 第三階段 |
| 熱力圖 | 第一次打開時由左到右依序淡入（以「欄」為單位，不是每格一個動畫） | ≤ 1.0 秒 | 第三階段 |
| 服務狀態 | 異常時橘點呼吸閃爍 3 次後停止 | 3 × 0.8 秒 | 第四階段 |
| 額度通知 | 點通知打開面板時，對應卡片亮一下 | 0.6 秒 | 第四階段 |
| 快捷鍵與右鍵選單 | 系統原生 | — | 第四階段 |

「第一次打開」的動畫（圓環、用量條、熱力圖）每次打開面板都播放；同一次開啟期間資料更新時只動改變的部分。

### 3. 效能量測（NFR-10，每個動畫都要做）

**方法**：`scripts/measure-panel-perf.sh` 以 Debug 版執行 App（`AUM_DEMO_PANEL=1 AUM_DEMO_PERF=1`，面板放在一般視窗，依固定時間表開啟、觸發每個動畫、關閉、再開關一次），用 `ps -o %cpu=,rss= -p <pid>` 每秒取樣。資料指向不會更新的假 `usage.json`，避免收集器寫檔的時刻混進取樣。Debug 版比 Release 慢，結果較保守。

| 階段 | 取樣 | 通過條件 |
|---|---|---|
| 面板開啟、靜止 | 開啟 3 秒後取 10 秒平均 | CPU ≤ 2% |
| 動畫播放中 | 觸發動畫的那幾秒的最大值 | 只記錄（作為回歸比較的基準），不設門檻 |
| 關閉後 1 分鐘 | 關閉 60 秒後取 30 秒平均 | **CPU ≤ 0.3%** |
| 第二次開關後 | 第二次關閉 5～18 秒的 RSS 最大值 | 不超過第一次關閉後 +5 MB（第一次開啟會載入 SwiftUI 與字型，RSS 不會回到開啟前，所以比較兩次關閉，確認沒有累積） |

- 結果（每個動畫一列）附在 PR 內文。Debug 版以環境變數（`#if DEBUG`）開關面板與觸發動畫，Release 不含這些字串。
- 限制：量測用一般視窗承載面板，不是 `MenuBarExtra` 的視窗（無法以程式點開選單列面板）；兩者都依同一套可見度判斷停止動畫，實機點開與關閉要手動確認一次。
- `ps` 的 `%cpu` 是近期的衰減平均，關閉後 1 分鐘的數字可能包含關閉前的殘留；以取樣 30 秒的平均降低誤差，若在門檻附近，用 `top -l` 或 Instruments 的 Time Profiler 再確認。
- 面板關閉時 `UsageStore` 每 60 秒的計時器（容許誤差 10 秒）仍會喚醒一次，這是第 1 節規則 1 的唯一例外，量測時包含在關閉後的取樣中。

### 4. 截圖與動畫紀錄

- 截圖用 `ImageRenderer`（設計 skill 第 8 節），不依賴螢幕；淺色與深色各一份。
- `ImageRenderer` 的限制：畫不出材質（`Material`、Liquid Glass）與 AppKit 實作的控制項（捲動視圖、`Toggle` 的開關、`Picker`、拖放與右鍵選單）。因此卡片用半透明填色（ADR-0008 第 2 節）、面板與設定的按鈕與開關自己畫，截圖時關掉捲動與拖放。
- `ImageRenderer` 拿不到 `withAnimation` 的中間影格，所以每個動畫都寫成一個 0…1 的進度值（`PanelMotion`），App 執行時由 `withAnimation` 驅動，截圖工具則以相同的曲線逐格指定進度，輸出 30 fps 的 PNG 序列再組成 GIF。深淺色切換的 GIF 是兩張截圖的交叉淡入示意，實際效果以實機為準。

## 考慮過的選項

| 選項 | 不採用的原因 |
|---|---|
| Metal shader／SceneKit 的 3D 效果（FR-25 原案） | 量測與維護成本高，設計圖沒有用到；之後有需要另寫 ADR |
| 選單列圖示的循環動畫（例如快用完時閃爍） | 選單列一直可見，違反 NFR-8；以小點與顏色表達 |
| 只量測「關閉後」 | 播放中的數字可以抓出意外的重繪迴圈（例如動畫結束後仍持續重算），作為回歸比較 |

## 影響

- FR-25 改寫為「依 ADR-0010 的動畫清單與規則」。
- 設計 skill 第 7 節「Mac 動畫」一列改為引用本 ADR。
- 每個加入動畫的 PR 都附量測結果。
